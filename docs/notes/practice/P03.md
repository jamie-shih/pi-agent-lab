## Lab 03 观察

- `getAvailable()` 数量：44（首个为 `openai/gpt-4`）
- `getModel("openai","gpt-4")`：`reasoning=false`，`contextWindow=8192`，`maxTokens=8192`
- `setModel`：是 — 切到 `openai/gpt-4-turbo`，第二轮回复 `switched-ok`
- 第一轮回复：`model-check-ok`
- `SessionManager.inMemory()`：是（避免 sessions 落盘）
- 卡点：在受限网络/sandbox 下会出现 `Connection error.` + `auto_retry_*`；完整出网后正常

## Key 管理方式（教程 4 种）

| 方式 | 我用了吗 | 注意 |
|------|----------|------|
| models.json 写 `apiKey` | ✅ | 勿提交 git（已 ignore） |
| 环境变量 | 否 | 内置 Provider 有白名单变量名 |
| auth.json | 目录里有文件，本 lab 未改用 | models.json 可只放模型定义 |
| `setRuntimeApiKey` | 否 | 运行时注入，优先级最高 |

优先级（高→低）：`setRuntimeApiKey` > auth.json > models.json `apiKey` > env

## 内网 / 自定义端点注意事项

核对清单（`api: "openai-completions"`；新版 OpenAI 内置也可能走 `openai-responses`）：

| # | 项 | 结论 |
|---|----|------|
| 1 | 端点可拼成 `{baseUrl}/chat/completions`（或对应协议路径） | 待有内网网关时填 |
| 2 | 支持 SSE `stream: true` | 硬性 |
| 3 | messages 为 `{role, content}` | 硬性 |
| 4 | chunk 有 `choices[0].delta.content`（或协议等价字段） | 硬性 |
| 5 | Bearer 或其它鉴权 | |
| 6–9 | max_tokens / tools / usage / reasoning | 按需 `compat` |

小差异 → `compat`；大差异 → 转换层 / `registerApiProvider`。  
不支持 tools 时清空工具集会让 Agent 退化成纯聊天——业务上要想清楚。

## 收获

- ModelRuntime 是「配置仓库」：`getAvailable` 按鉴权过滤，`getModel` 同步精确查找且不查 Key
- 同一 Session 可 `setModel` 切换，对话历史保留（适合成本路由）
- 默认会合并内置 Provider 模型目录，所以 available 远多于 models.json 里手写的那几条
