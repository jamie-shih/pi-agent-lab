# P02 · 工作机制

- 教程：https://dg-ai-notes.pages.dev
- Lab：`npm run lab:02`
- 日期：2026-10-01
- 模型：`openai/gpt-4`
- 回复内容：`Coding assistant ready.`（三词，符合 prompt）

## 关键 API

- `ModelRuntime.create()` / `getAvailable()` — 解析 `PI_CODING_AGENT_DIR` 下配置，选出可用模型
- `createAgentSession({ model, modelRuntime })` — 打开会话
- `session.subscribe(listener)` — 订阅会话事件流
- `session.prompt(text)` — 发起一轮用户输入，驱动 Agent Loop
- `session.dispose()` — 释放资源

## 事件流观察

一次 `prompt` 的外壳顺序（打印到 stderr 的非 update 事件）：

```text
agent_start
  turn_start
    message_start → message_end   # 第 1 条消息边界
    message_start → message_end   # 第 2 条消息边界
    message_start + text… → message_end   # 第 3 条：assistant 正文
  turn_end
agent_end
agent_settled
```

计数：

| 事件 | 次数 | 含义（本次观察） |
|------|------|------------------|
| `agent_start` / `agent_end` | 1 / 1 | 一次 agent 运行生命周期 |
| `turn_start` / `turn_end` | 1 / 1 | 一轮 turn（本 prompt 无多步 tool loop） |
| `message_start` / `message_end` | 3 / 3 | 三条消息各一对边界（含用户侧/系统侧与 assistant） |
| `message_update` | 6 | 流式增量（含 `text_delta`；脚本对非 delta 的 update 静默） |
| `agent_settled` | 1 | 本轮工作收尾、可视为空闲 |

要点：

- 打字机效果来自 `message_update` + `assistantMessageEvent.type === "text_delta"`
- 没有工具调用时，看不到 tool 相关事件；后面做工具 lab 时对比会更明显
- `agent_settled` 在 `agent_end` 之后，适合挂「全部完成后再做清理/上报」的逻辑

## 与三层架构的对应（对照教程第 2 章）

教程：[第 2 章 · 先看全貌](https://github.com/buchidonggua/dg-ai-notes/blob/main/pi-agent/pi_sdk_learn/docs/第2章-先看全貌-搞懂pi-agent工作机制.md)

第 2 章说的「三层」不是 npm 包分层，而是 **Session / Runtime / Tool**（中间还有 ExtensionRuntime）：

```text
Session      prompt / subscribe / dispose     ← Lab 02 直接操作的唯一层
   │ 创建时注入
Runtime      ModelRuntime / ResourceLoader /
             SessionManager / SettingsManager ← createAgentSession 默默装好
                 │
ExtensionRuntime  pi.on / registerTool        ← 本 lab 未碰（P05/P06）
                 │
Tool         read/bash/edit/write 等          ← 本 lab 未触发调用
```

### Lab 02 事件图落在哪一层？

整张事件图都是 **Session 层通过 `subscribe` 透出的过程信号**；真正干活的是 Session 背后 Runtime 驱动的 Agent Loop（ReAct）。

```text
你写的代码（Session API）          事件流（subscribe 看到的）
─────────────────────────          ─────────────────────────
createAgentSession(...)     →      （内部装 Runtime 四件套 + 默认 Tool）
session.subscribe(...)      →      只注册回调，不阻塞
session.prompt("三词…")     →      agent_start
                                     turn_start          ← 一轮 ReAct
                                       message_* ×3      ← 消息进出会话
                                       message_update×6  ← 流式正文（含 text_delta）
                                     turn_end            ← 本轮结束（无工具，故只有 1 轮）
                                   agent_end
                                   agent_settled         ← Session 扩展事件（空闲）
session.dispose()           →      清监听 / 中止后台任务
```

| 架构层 | Lab 02 有没有动 | 和事件的关系 |
|--------|-----------------|--------------|
| **Session** | ✅ `prompt` / `subscribe` / `dispose` | 事件全部从这里订阅；你 90% 代码都在这层 |
| **Runtime · ModelRuntime** | ✅ 创建时注入 | 决定 `openai/gpt-4`；请求走 `pi-ai`，事件里看不到 Key/配置细节 |
| **Runtime · 其余三者** | 默认启用，未改 | Settings / SessionManager / ResourceLoader 在后台；本 turn 无 compaction 等事件 |
| **ExtensionRuntime** | ❌ 未挂 | 没有 `pi.on` 钩子；P06 才动 |
| **Tool** | 已默认装上，但未调用 | 所以**没有** `tool_execution_start/end`，也**没有**第二轮 `turn_*` |

### 和教程「带工具」示意的差别

教程第 2 章末尾用「当前目录有哪些文件？」会看到大致：

```text
agent_start → turn_start → … → tool_execution_* → turn_end
            → turn_start → …assistant 正文… → turn_end → agent_end
```

那是 **两轮 turn**（想调工具 → 再根据工具结果回答）。  
Lab 02 只问「三词回复」，模型直接答完 → **一轮 turn**，事件壳更短。

### npm 包三层 vs 架构三层（别混）

| npm 包 | 角色 | 对应架构面 |
|--------|------|------------|
| `@earendil-works/pi-coding-agent` | 外壳：导出 `createAgentSession` / `ModelRuntime` | Session API + Runtime 组装 |
| `@earendil-works/pi-agent-core` | Agent Loop / 状态 | turn / message / tool 事件的引擎 |
| `@earendil-works/pi-ai` | 多 Provider LLM | ModelRuntime 真正发请求的底层 |
