# P07 · 封装成服务

- 教程：[第 7 章](https://github.com/buchidonggua/dg-ai-notes/blob/main/pi-agent/pi_sdk_learn/docs/第7章-准备上线-把Agent封装成服务.md)
- Lab：`npm run lab:07`（`labs/07-sse-service`）

## 目标形态（CLI / HTTP / SSE）

| 方式 | 本课 |
|------|------|
| TUI / print / RPC | 了解即可（RPC 适合非 Node 宿主） |
| **进程内嵌 SDK + Express SSE** | ✅ `POST /chat` 单接口流式 |

组装：P04 人设 + P05 `query_data` + P06 limit guard → Web。

## 部署检查清单

- [ ] `PI_CODING_AGENT_DIR` / Key 不进镜像层明文（用 secret / env）
- [ ] 生产反向代理关缓冲（`X-Accel-Buffering: no` 已设）
- [ ] 单 session 并发：429 或改为每用户一 session
- [ ] 客户端断开会 `abort`
- [ ] `/health` 可探活

## Lab 观察（跑完后填）

- 浏览器能否打字机输出：服务已起；用 curl 验证见下
- 工具卡片是否出现 `query_data`：✅ SSE `tool_start` / `tool_end`
- curl `-N` 是否看到 `data: {"type":"text"...}` 与最终 `done`：✅

curl 实跑摘要：华东笔记本 → `query_data(地区=华东)` → 文本「…笔记本电脑共售出15台」→ `done`

踩坑：客户端断开请监听 **`res.on("close")`**，不要用 `req.on("close")`——POST body 读完也会触发 request close，会误 `abort`。

## 收获

- 进程内嵌 SDK：`subscribe` + `prompt` + `abort` 三个能力即可桥接 SSE
- 单接口 POST `/chat` 比拆成发/收两条连接更简单
- 实战链路：P04 人设 + P05 工具 + P06 守卫 → Web
